# Phase 2 学习手册（实操版）

## 1. 学习路线（4 天）

- Day 4：接口与方法集（10, 11）
- Day 5：并发与 select（12, 13）
- Day 6：context 与并发安全（14, 15）
- Day 7：错误处理与反射边界（16, 17）

## 2. 每章“最低完成动作”

每章都至少完成下面 4 步：

1. 运行章节入口
2. 修改一处代码并再次运行
3. 阅读对应 `internal` 包核心函数
4. 跑该包测试并理解断言

## 3. 章节实操建议

### 10 接口与类型系统

- 把 `any` 输入换成不同类型，观察类型切换输出
- 给 `MessageSender` 传空 Notifier，理解错误返回

### 11 方法集与接收者

- 对比值接收者和指针接收者在状态更新上的差异
- 思考：为什么某些类型“看着像实现了接口”但编译不过

### 12 goroutine 与 channel

- 改 worker 数量，观察执行结果一致性
- 尝试自己增加一个处理阶段（如过滤偶数）

### 13 select 模式

- 调整超时时间，观察 timeout 分支变化
- 理解超时不是异常，而是可预期控制流

### 14 context 取消

- 改 `WithTimeout` 时长，观察完成任务数变化
- 重点看“收到取消信号后如何尽快收敛”

### 15 sync 并发安全

- 增大 goroutine 数量，验证计数是否仍正确
- 对比互斥锁和原子计数器的用途边界

### 16 错误处理

- 观察错误包装链，理解 `%w` 的价值
- 用 `errors.Is/As` 而不是字符串匹配做分类

### 17 reflect 与 unsafe

- 查看结构体字段 tag 的读取结果
- 明确：`unsafe` 是“了解机制”，不是常规业务手段

## 4. 如何判断你学会了

你应当能独立回答：

1. 接口隐式实现解决了什么工程问题？
2. goroutine 为什么会泄漏，怎么防？
3. 为什么错误包装比直接打印更重要？
4. 什么时候该用 mutex，什么时候可用 atomic？
5. 为什么 `unsafe` 要谨慎使用？

## 5. 常见问题（FAQ）

### Q1：我能跳过 Phase 1 直接看 Phase 2 吗？

不建议。Phase 2 的很多概念依赖 Phase 1 的语法和函数基础。

### Q2：看不懂并发怎么办？

先只看单个 goroutine 的行为，再增加一个 channel，再引入 select，不要一次看完整工程。

### Q3：测试失败怎么办？

先确认当前目录在 `phase2/`，然后重新执行 `go test ./...`。如果是自己修改后失败，回看断言对应的预期行为。

### Q4：为什么示例拆成 `cmd` 和 `internal`？

这是常见工程组织方式：`cmd` 放入口，`internal` 放实现，便于复用、测试和维护。
